# Immediate native data binding

`syncInstantSample(project, options)` is a pure data boundary: no DOM, view, camera, timers, storage or network calls. It invokes unchanged native Studio writers and the native allocator. The input project is never changed in place.

Options: `stage`, native `values`, optional opaque `ref`, native `target` (or `selection`), `recordId`, `activeIndex`, `shell` (default 0), `face` (default O), `cell`/`start` (default 1), `mode` (default facets), `tableId`, `reuseSeed` and optional record ID factory `makeId`.

Return: `{project,ref,selection,records,record,valid,error}`. Retain the returned ref for the next edit of that binding. An incomplete/invalid edit returns the original last-valid project and ref, `valid:false` and a short error. It does not create a partly valid row or record.

- Favourites accepts a native field object or its three-item array. The array has independent row/record identities at consecutive facets 1, 2 and 3. `activeIndex` chooses which result is selected; the other records remain in place.
- Skills, goals, dates, timing, family and travel use the real native row writers. Dates/timing require their native guided form's title and date. Other validation remains with the source writer.
- Avatar accepts actual parameter IDs. Each native parameter retains its own table row and record identity, with every current parameter record associated with the same selected facet (default 1). The adjacent result can display both current values. Subsetting or changing the current parameter keys finds previous record IDs by table/row, not array index.
- Allocate accepts `{tableId,shell,face,start,mode,titleColumn}`. Rows keep their native IDs; repeated edits do not duplicate their records. Facet allocation cycles consecutive facets; stack targets preserve their layer addresses.

Pass `reuseSeed:false` for a newly selected non-seed colour/face/facet. This prevents a new owner reusing the original QuickStart favourite row. The root UI may seed the three starter favourites once at Red O1–O3, then cache their returned refs by target key. Selecting another facet should only read its record or show a blank input; call this helper when the person edits.

An explicit `recordId` adopts that chosen visible record, preserving its ID and existing links. If the original record belongs to a different native collection, a suitable native row is created once and returned in the ref. Passing the same ref with an explicit new target intentionally moves that association without changing its row/record identity. Keep separate refs per owner unless that move is intended.

Canonical field/data shape is generated by the real `allocateTable` function in a temporary one-row project, then merged into the same live record ID/address. Native row fields override matching fields; unrelated source fields and an existing asset are retained. The source allocator stores a favourite's `What resonates` in `record.fields` and `record.data`, while `record.note` can be empty. Display the current stage's actual field values directly beside the view.

This helper never calls a viewer reset or changes orientation. The UI keeps one mounted native AuraView, updates its current project/selection, and keeps the torus beside the changing field card.

Run `node test-instant-data.mjs`. Tests cover all nine stages and seven contexts, 756 repeated native edits, stable identities, favourites 1–3, co-located avatar values, per-facet ownership and return, explicit moves, exact field updates, incomplete input and unchanged links. Real global storage and fetch are made to throw during these tests.
