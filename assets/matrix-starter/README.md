# Native Matrix Studio starter activity

Private prototype, 29 October 2026. This iframe runs actual Studio data writers and selected source UI. It complements the unchanged document readings.

Open `index.html?stage=favourites&example=memory`. Stages: `favourites`, `skills`, `goals`, `dates`, `timing`, `travel`, `family`, `avatar`, `allocate`. `allocation` is accepted as an alias. Contexts: `kitchen`, `garden`, `fermentation`, `event`, `memory`, `travel`, `creative`.

The host must be copied beside `matrix-studio/` and `aura-learning-native.css`. The shared Matrix directory supplies the unchanged real renderer/runtime and `viewer.js`. Entry loads its local Three script before the renderer module. `entry.js` opens the real viewer in this same iframe with the updated sample project; Back restores the previous activity and current project. No project is passed in a URL or stored in the parent.

`mountStarter(root,{stage,example,project?,showMatrix?})` returns `{project,stage,reset(),destroy()}` (project and stage are getters). `showMatrix(project,selection,{stage,example})` receives the real validated project and source target. If no callback is supplied, the root emits the local DOM event `aura-sample-matrix` with those fields. This is not a parent-window message. One mounted starter is intended per iframe.

`sample-store.js` owns module memory only. Native `travel-data.js` imports its `sampleStorage` under a **lexical** `localStorage` alias. The real global localStorage is neither replaced nor accessed. The actual `mountLife` family UI therefore reads and writes the same in-memory fixture as the starter forms. Reset replaces it with a fresh clone. The independent iframe realm prevents separate examples sharing this module state.

`build-starter.py` copies the native data modules and `life-ui.js`, redirects their common imports to the viewer's unchanged runtime, extracts actual QuickStart `renderFavourites`, `renderGuided`, `renderAllocation` and their UI helpers, and extracts native `tripForm`. The source writers `saveSectionEntry`, `saveLife`, `saveTiming`, `saveTrip`, `allocationPlan` and `allocateTable` remain unchanged. The UI changes are confined to the sample state/routing boundary, source-relative imports, native family scope, callback handoff and truthful sample messages. `upstream-manifest.json` records upstream and output hashes, function ranges and exact patch purposes. `native.css` and LICENCE.md are unchanged source files. `starter.css` makes the iframe layout responsive, light and at least 18px, with keyboard focus and reduced-motion support.

Favourites retains the source's three meaningful groups: a value, an experience and something loved, each with its explanation. Skills, goals, dates, timing and avatar use the real native guided form code. Family uses `mountLife`, not QuickStart's family-to-adult-dating alias. Dating launch cards and import/export entry points are excluded. Travel retains the source form and its fields; suggestions are bundled source JSON, and the host callback uses the real `saveTrip`. Allocation previews the real plan, retains table/row references, adds actual facet or stack records, and opens their real native geometry. The sampled projects, starter defaults and record links come from the shared seven-context fixture register.

No profile photographs, real file imports, remote services, browser persistence, URL/history changes, background reminders or automatic agent actions are enabled. Inputs edit a fictional sample in memory; the activity is not a personal-record capture service. Native source semantics are retained: I/O addresses alone do not enforce sharing permissions.

Run bundled Python on `build-starter.py`, then `node --check starter.js`, `node --check entry.js` and `node test-starter.mjs`. The test exercises every context through native favourites → table → stack allocation → selected-record recall, confirms all other stage writers, and deliberately makes real global localStorage and fetch throw. Browser layout/keyboard testing remains a separate integration check.
